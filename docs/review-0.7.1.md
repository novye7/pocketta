# 0.7.1 SVG 圆角修复与视觉回归

日期：2026-11-14。环境：macOS、agent-browser Chromium、ego-lite 已安装扩展。

## 问题与修复

742 × 36 的黑色按钮使用 `border-radius: 9999px`。旧实现分别将横、纵半径限制到宽、高的一半，生成 `rx=371, ry=18` 的椭圆；CSS 按相邻圆角之和计算一个公共缩放系数，正确结果应为 `rx=ry=18` 的胶囊。

- 按 CSS Backgrounds 的重叠圆角规则，同时缩放四个角、两个轴；百分比先按原始边框盒解析，再处理重叠。
- 边框内轮廓和内阴影环从已归一化的外圆角向内收缩。等宽同色实线边框改为内外轮廓之间的填充区域；椭圆中心线的 SVG 描边不能准确表达 CSS 内外椭圆。
- 未支持的圆角运算表达式明确提供 PNG 回退，不再把 `calc(...)` 静默当作零。
- 所有注入模块及 manifest 升至 0.7.1，避免页面中的同版本保护跳过新版代码。

## 独立视觉参照

新增 `tests/fidelity.browser.js` 并纳入默认浏览器回归。参照来自浏览器对实际 DOM 的截图，独立于 capture、PNG 导出器和 SVG 几何计算；比较对象为实际导出的 SVG。

16 类场景在 1×、2× 下分别检查：横向/竖向胶囊、圆、百分比椭圆、单大角、重叠及百分比非对称圆角、单轴为零、胶囊及非对称粗边框、胶囊及非对称裁剪、椭圆长度、小圆角、直角和内阴影环。

每个组件单独统计。RGB 最大通道差超过 32 计入原始差异；若双方颜色均落在对方一物理像素邻域的颜色范围内，则标为边缘容差。其余差异占比须小于 0.7%。保留原始计数、带颜色标记的并排图和 JSON 报告，避免只看一个通过标记。

用最终比较规则运行修复前的 SVG 渲染器，两个倍率均只有 5/16 通过；宽按钮差异为 22.27% / 21.56%。修复后两个倍率均为 16/16 通过；宽按钮的原始差异像素均为零。容差没有掩盖原始问题。

## 如何继续避免同类问题

新增或修复一种 CSS 能力时，补齐该类型的常见值、极端值及组合截图用例，并以浏览器截图作为独立参照。真实组件按局部区域对比，保留表单状态及文字样例；已知无法可靠表达的效果明确提供 PNG 回退。

本次新用例重点覆盖圆角几何，不代表全部 CSS、字体、原生表单控件或设计软件导入效果都已验证。SVG 与 CSS 的边缘抗锯齿及分层合成仍可能有细微差异。广泛回归可以提前发现一类问题，但不能保证任意网页在所有软件中逐像素一致。
