# 0.1.0 代码 review 与验证

日期：2026-11-05。环境：macOS、ego-lite / Chromium 156。

## Review 范围与结果

已逐项检查清单权限、注入入口、选取事件拦截、克隆样式与状态、异步取消、资源读取失败、下载和退出清理。当前没有已知的阻塞性代码问题；扩展已安装并启用，原生工具栏点击后的完整注入流程尚未完成自动化复测。

Review 中修复了以下问题：

1. 重新选择后，范围按钮可能沿用上一次的可点击状态，导致空选择访问错误。现在清空选择时同时禁用扩大、缩小和导出；已在真实浏览器回归验证。
2. 原始组件中的 `<style>` 可能干扰固化后的样式。现在克隆完成后移除原始样式表，仅保留生成的伪元素规则。
3. popup 校验地址之后仍可能发生页面导航。注入脚本增加独立的 origin 校验，确保工具仅在 `https://chatgpt.com` 启动。

## 已知边界

Canvas、视频、iframe、公开 Shadow DOM 不支持；网页字体、变换、复杂滤镜、外部 SVG 引用可能存在外观差异。导出不会自动展开折叠内容或内部滚动区。图片资源必须允许页面读取。以上限制已在 README 说明。

- 在用户完成原生目录选择后，扩展管理页确认 0.1.0 已启用。
- 补充 `_execute_action` 快捷键 `Alt+Shift+E`；重新加载扩展后，通过实际扩展环境的 `chrome.commands.getAll()` 确认 macOS 绑定为 `⌥⇧E`。
- 真实 `chrome-extension://…/popup.html` 页面加载正常，HTML、CSS、JavaScript 资源可用；在非 ChatGPT 活动页点击启动，显示预期的页面提示。
- 快捷键修改已检查 Chrome Commands API 规范，未增加任何权限。

当前自动化接口无法触发原生工具栏 action，原生桌面 UI 捕捉也不可用。因此，工具栏点击产生的 `activeTab` 临时授权、隔离环境注入与下载这一完整链路尚未自动化复测；页面内的代码验证不能代替这一检查。保留最小权限，没有为测试扩大站点访问范围。
